# Standing rules for slice agents (orchestrator-maintained)

Status: a copy maintained by the orchestrator. Rules 3, 4 and 8 are superseded where marked; the rest is current.

1. CI and merge state are YOUR job. After every push, run `gh pr checks <n>` until nothing is pending. If a check fails, read the log (`gh run view <run> --log-failed`), decide whether it is caused by your change, and fix it. A known flake (see `bd memories ci-rust-job-slowness`: AVA timeout in design-data-mcp under load) may be re-run once; say so. Check `gh pr view <n> --json mergeable,mergeStateStatus`; if the PR is CONFLICTING or behind, merge/rebase origin/main, resolve, re-run the affected tests, and push. Never report 'done' with a red or pending required check without saying so first.
2. CLI version rule (tools/cli-minimum-gate/gate.sh): bump sdk/cli/Cargo.toml (and sdk/Cargo.lock) ONLY if the current Cargo version already has a release tag `design-data-cli@<version>` (`git ls-remote --tags origin 'design-data-cli@*'`). An unreleased version absorbs new commands and behavior without a bump. Never change dataset.json `requires.cli` in a feature PR (the gate passes when requires.cli equals the checkout's CLI version and it is unreleased); raising it is a separate release-time step (bead p6ga.27). Releases only happen when no changesets are pending and the Version Packages PR is merged (see .github/workflows/release.yml).
3. (SUPERSEDED: the orchestrator's briefs no longer use `gh stack`; use plain `git fetch` + rebase/merge origin/main and push only your own branch with `--force-with-lease`.) Dependent work: if your branch depends on another open PR, use `gh stack` (v0.3.0; `gh stack init`, `gh stack add`, `gh stack submit`, `gh stack sync`) instead of copying commits, so the parent merging does not force a hand rebase. Ask the orchestrator if unsure.
4. (SUPERSEDED: owner rule 2026-11-22: ALWAYS tick the CLA checkbox; do not leave it unticked or ask.) Do not use `git stash`, do not touch \~/repos/spectrum-design-data directly, do not merge PRs, do not tick CLA/CONTRIBUTING boxes, do not close beads.
5. End your report with 'Decisions I made' (each labeled meaning / contract / local-reversible / scope) and 'Questions for Garth' (blocking first).
6. PR bodies: never write them to a shared path such as /tmp/pr.md (agents overwrote each other's PR bodies on 2026-11-19). Use a private file (`mktemp`) or `gh pr edit --body-file` with a file inside your own worktree (and do not commit it), then re-read the body with `gh pr view <n> --json body` to confirm it is yours.
7. Worktree hygiene: `pnpm install` chmods tools/design-data-mcp/src/cli.js to 755, which dirties the tree and makes `gh stack sync` refuse. After installing run `chmod 644 tools/design-data-mcp/src/cli.js`. paseo.json is excluded via the repo's info/exclude; never commit it. Never commit either file.
8. (SUPERSEDED: the orchestrator's briefs no longer use `gh stack`; use plain `git fetch` + rebase/merge origin/main and push only your own branch with `--force-with-lease`.) gh stack hazard (2026-11-19): `gh stack sync` / `submit` rebase and force-push EVERY branch in the stack, including the parent branch owned by another agent. That rewrote PR [#1952](https://github.com/adobe/spectrum-design-data/issues/1952)'s history under its author and broke CI on both PRs. Only push the branch you own. Prefer plain `git fetch` + `git rebase origin/<parent>` + `git push --force-with-lease origin <your-branch>`; use `gh stack init/add` only to link the PR base, and ask the orchestrator before running `sync` or `submit` when someone else owns the parent branch. A branch you own that is already pushed is only force-pushed with --force-with-lease.
