# Spectrum Studio

Read `docs/spectrum-studio/AGENTS.md` before changing anything under `docs/spectrum-studio/`. It holds the working rules, the domain map, and the skills and rules in `docs/spectrum-studio/.agents/`.

* **North star:** read `docs/spectrum-studio/docs/master-migration-plan.md` before planned or unplanned Studio work. Apply its agent core and work-alignment protocol in the existing plan/reasoning, then load only relevant epic details and skills. Exact package-wide reproduction with preserved identities/references precedes repository cutover; approximate agreement is refinement evidence, not completion. The roadmap owns delivery status and the gap register owns alignment evidence. This direction never authorizes additional scope or writes.
* **Systems-first check:** before planning or implementing changes to authored data, relationships, naming, formulas, rules, generators, or outputs, read and apply [parametric-systems-design](../../.ai/skills/parametric-systems-design/SKILL.md), even when the request describes only UI. State the data owner, shared derivation path, and affected consumers in the existing plan or reasoning. Pure styling changes only need to confirm system behavior is unchanged.
* The package keeps `tsx` check scripts and Playwright instead of AVA, and keeps its debt in `docs/known-debt.md` instead of beads. The root rules otherwise apply.
* Differences from design-data are diagnostics, never failures. Do not add load-time throws or alignment gates.
* Changes that touch persisted design data must keep Changes parity.
* **Development browser data:** follow `AGENTS.md`, Working rule 7. When a schema, model or default-data enhancement makes existing local browser state incompatible or causes issues, silently reset Studio-owned settings and working/saved snapshots to current shipped defaults. Do not ask whether to preserve or retroactively migrate local edits, or build preservation machinery unless requested. Compatible edits keep normal Save/Cancel and scoped-reset behavior; never clear unrelated storage or repository data.
* **Token entry:** read the `component-catalog` skill's Token entry contract. `TokenComboBox` already supports token-name/value search, list selection, direct custom values, Enter/blur acceptance, Escape and keyboard clearing. Do not add Manual/Custom sentinels, companion inputs, local key handlers or picker forks for these uses. Configure the shared component and keep domain validation in its existing owner.
* **Bounded verification:** inspect exact IDs with `pnpm check:list --only <id,...>`. Verify the changed element and immediate relevant relationships. The inventory declares scope, resource class and prerequisites; unknown checks are not assumed small. Prefer `types-files --files <file,...>` and `lint-files --files <file,...>` over whole-project checks. Broader local scope requires an explicit user request and `--scope-approved`; named heavy checks require approval and `--heavy-approved`. Flags record permission, not grant it. Comprehensive CI remains unchanged; `pnpm test:ci` is not a local default.
* **Scope and stopping:** record the requested outcome, non-goals, selected checks and stopping condition in existing reasoning. A cutoff or incomplete cleanup stops work; ask before retrying, increasing limits or starting replacement work. Prefer direct work, not automatic delegation. See Studio's `docs/agent-execution.md` for provisional resource limits and client-enforcement gaps.
* **Browser checks:** run only when needed. Common interaction and rendering checks belong in isolated Storybook stories, not app pages. Before any actual app-page browser testing, ask the user for explicit permission, explain why a story cannot cover the behavior, and name the scope. General implementation or verification approval is not permission; if the user is unavailable, skip and report the gap.
* **Search scope:** keep discovery and content searches inside `docs/spectrum-studio/`, with `packages/` as the only source-package exception. Never search dependency, vendor, cache, generated-output or report directories, including `node_modules`, `.pnpm` and `.git`. Read explicitly named instruction files directly instead of searching their directories.
* **Device resources:** default to one scoped search. Shared admission allows at most two small invocations (256 MiB/30 seconds each, 512 MiB combined) or one exclusive approved heavy invocation (1 GiB/60 seconds). Deadlines cover complete selections; accounting includes runner overhead and owned descendants. Busy means not run: continue independent work without waiting, polling or automatic retries. Never exceed 10 concurrent ripgrep processes; shell `rg` uses `--threads 1`. Browser tests use `--workers=1`. Do not bypass admission, overlap heavy jobs or start duplicate servers. On stalls/cutoffs, stop task-owned work and ask before retrying; ask before costly baselines or repository copies. Native sampling is not a hard OS memory boundary.
